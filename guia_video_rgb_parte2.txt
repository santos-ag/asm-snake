7.5 COMBINAR BOTÕES EM UM SINAL DE 4 BITS
------------------------------------------

  Precisamos juntar os 4 botões (cada um 1 bit) em um único sinal
  de 4 bits. Usamos um Splitter "ao contrário" (combinando sinais).

  PASSO 1: Adicionar Splitter

    a) Adicionar: Wiring → Splitter
    
    b) Configurar:
       - Bit Width In: 4 (saída combinada)
       - Fan Out: 4 (4 entradas separadas)
       - Appearance: pode deixar padrão
    
    c) IMPORTANTE: O Splitter pode tanto separar quanto combinar!
       - Se você conectar no lado "largo" (4 bits), ele separa
       - Se você conectar nos lados "estreitos" (1 bit cada), ele combina
  
  PASSO 2: Conectar os botões
  
    Conectar cada botão à entrada correspondente do Splitter:
    
    ┌────────────────────────────────────────────────────────────┐
    │                                                            │
    │  UP ────────────► Bit 0 ─┐                                 │
    │                          │                                 │
    │  RIGHT ─────────► Bit 1 ─┼───► Splitter ───► buttons (4b)  │
    │                          │                                 │
    │  DOWN ──────────► Bit 2 ─┤                                 │
    │                          │                                 │
    │  LEFT ──────────► Bit 3 ─┘                                 │
    │                                                            │
    └────────────────────────────────────────────────────────────┘

7.7 VERIFICAR ENDEREÇO E GERAR SAÍDA
-------------------------------------

  Só devemos retornar o estado dos botões quando o processador
  acessar o endereço correto (0x900).

  PASSO 1: Comparar endereço

    a) Adicionar: Arithmetic → Comparator
       - Data Bits: 32
    
    b) Conectar:
       - Entrada A: pino "addr"
       - Entrada B: Constante 0x00000900
    
    c) Usar saída: A = B (igualdade)
       - Resultado: sinal "addr_match"

  PASSO 2: Criar sinal de leitura válida

    a) Adicionar: Gates → AND Gate (2 entradas)
    
    b) Conectar:
       - Entrada 1: sinal "addr_match"
       - Entrada 2: pino "re" (read enable)
    
    c) Saída: sinal "read_valid"

  PASSO 3: Multiplexar saída

    a) Adicionar: Plexers → Multiplexer
       - Data Bits: 32
       - Select Bits: 1
    
    b) Conectar:
       - Select: sinal "read_valid"
       - Input 0: Constante 0x00000000 (retorna 0 se não é leitura válida)
       - Input 1: sinal "buttons_32" (retorna estado dos botões)
    
    c) Saída: conectar ao pino "data_out"

  DIAGRAMA COMPLETO:
  
    ┌───────────────────────────────────────────────────────────────────┐
    │                                                                   │
    │  addr ────────►[  =  ]◄──── 0x900                                │
    │                  │                                                │
    │                  ▼                                                │
    │  re ──────────►[AND]────► read_valid                             │
    │                              │                                    │
    │                              ▼                                    │
    │  0x00000000 ───►[  MUX  ]◄─── (select)                           │
    │                    │                                              │
    │  buttons_32 ──────►│                                              │
    │                    │                                              │
    │                    ▼                                              │
    │                data_out                                           │
    │                                                                   │

7.9 TESTE DO SUBCIRCUITO
-------------------------

      addr = 0x00000900
      re = 1
      Pressionar botão UP

    EXPLICAÇÃO:

  TESTE 2: Múltiplos botões pressionados

    Configuração:
      addr = 0x00000900
      re = 1
      Pressionar UP e RIGHT simultaneamente
    
    ESPERADO: data_out = 0x00000003
    
    EXPLICAÇÃO:
      UP (bit 0) = 1, RIGHT (bit 1) = 1
      Binário: 0011 = 0x3

  TESTE 3: Endereço errado

    Configuração:
      addr = 0x00001000 (endereço errado)
      re = 1
      Pressionar qualquer botão
    
    ESPERADO: data_out = 0x00000000
    
    EXPLICAÇÃO:
      Endereço não bate, então retorna 0

  TESTE 4: Read enable desativado

    Configuração:
      addr = 0x00000900 (correto)
      re = 0 (desativado)
      Pressionar qualquer botão
    
    ESPERADO: data_out = 0x00000000

9. CONFIGURAÇÃO DO ADDRESS DECODER
================================================================================

9.1 O QUE É O ADDRESS DECODER?
-------------------------------

O Address Decoder é o "carteiro" do sistema. Quando o processador
quer acessar um endereço, o decoder descobre qual componente deve
responder.

ANALOGIA:

  Processador: "Quero escrever no endereço 0x500!"
  
  Address Decoder: "Deixa eu ver... 0x500... Ah! Isso é o Video RGB!
                    Vou mandar esses dados para lá."

FUNÇÕES DO ADDRESS DECODER:
  1. Analisar o endereço vindo do processador
  2. Gerar sinais de "chip select" para cada componente
  3. Rotear dados de leitura de volta para o processador


9.2 TABELA DE DECODIFICAÇÃO
----------------------------

  ┌──────────────────┬──────────────┬─────────────┬─────────────┐
  │ Faixa Endereço   │ Componente   │ Chip Select │ Operação    │
  ├──────────────────┼──────────────┼─────────────┼─────────────┤
  │ 0x0000 - 0x1FFF  │ ROM          │ ROM_CS      │ Leitura     │
  │ 0x0400 - 0x07FF  │ Video RGB    │ VIDEO_CS    │ Escrita     │
  │ 0x0800           │ Score        │ SCORE_CS    │ Escrita     │
  │ 0x0804           │ Game Over    │ GOVER_CS    │ Escrita     │
  │ 0x0900           │ Buttons      │ INPUT_CS    │ Leitura     │
  │ 0x1000 - 0x2FFF  │ RAM          │ RAM_CS      │ Leit/Escr   │
  └──────────────────┴──────────────┴─────────────┴─────────────┘


9.3 CRIAR OS COMPARADORES
--------------------------

Vamos criar um comparador para cada faixa de endereço.

DECODER PARA ROM (0x0000 - 0x1FFF):

  Condição: addr < 0x2000

  1. Adicionar: Arithmetic → Comparator (32 bits)
  
  2. Conectar:
     - A: barramento de endereço (addr)
     - B: Constante 0x00002000
  
  3. Usar saída: A < B
     - Resultado: ROM_CS

  VISUALIZAÇÃO:
  
      addr ────►[  <  ]◄──── 0x2000
                  │
                  ▼
               ROM_CS


DECODER PARA VIDEO RGB (0x0400 - 0x07FF):

  Condição: (addr >= 0x400) AND (addr < 0x800)

  1. Comparador 1: addr >= 0x400
     - Adicionar: Arithmetic → Comparator
     - A: addr, B: 0x400
     - Saída: A ≥ B → sinal "video_ge"
  
  2. Comparador 2: addr < 0x800
     - Adicionar: Arithmetic → Comparator
     - A: addr, B: 0x800
     - Saída: A < B → sinal "video_lt"
  
  3. Combinar: Gates → AND
     - Entradas: video_ge, video_lt
     - Saída: VIDEO_CS

  VISUALIZAÇÃO:
  
      addr ──┬──►[ >= ]◄── 0x400 ───► video_ge ──┐
             │                                    ├──►[AND]──► VIDEO_CS
             └──►[  < ]◄── 0x800 ───► video_lt ──┘


DECODER PARA INPUT/BUTTONS (0x0900):

  Condição: addr == 0x900

  1. Adicionar: Arithmetic → Comparator
  
  2. Conectar:
     - A: addr, B: 0x900
  
  3. Usar saída: A = B
     - Resultado: INPUT_CS


DECODER PARA RAM (0x1000 - 0x2FFF):

  Condição: (addr >= 0x1000) AND (addr < 0x3000)

  1. Comparador 1: addr >= 0x1000
     - Saída: ram_ge
  
  2. Comparador 2: addr < 0x3000
     - Saída: ram_lt
  
  3. AND Gate:
     - Saída: RAM_CS


9.4 GERAR SINAIS DE WRITE ENABLE
---------------------------------

Alguns componentes só aceitam escrita. Precisamos combinar
o chip select com o sinal de escrita do processador.

  RAM_WE = RAM_CS AND mem_write
  VIDEO_WE = VIDEO_CS AND mem_write

  Implementação:
  
    1. Para cada componente com escrita:
       
       a) Adicionar: Gates → AND Gate (2 entradas)
       
       b) Conectar:
          - Entrada 1: Chip Select do componente
          - Entrada 2: Sinal mem_write do processador
       
       c) Saída: sinal de write enable específico


9.5 MULTIPLEXAR DADOS DE LEITURA
---------------------------------

Quando o processador lê dados, precisamos escolher de qual
componente vem a resposta.

  ┌─────────────────────────────────────────────────────────────────┐
  │                                                                 │
  │  ROM.data_out ─────────────► ┌────────────────┐                │
  │                              │                │                │
  │  RAM.data_out ─────────────► │   MULTIPLEXER  │ ───► data_in   │
  │                              │     (para o    │     (processador)
  │  Input.data_out ───────────► │   processador) │                │
  │                              │                │                │
  │  (zero/default) ───────────► └───────┬────────┘                │
  │                                      │                         │
  │                                      │                         │
  │  Seleção baseada nos chip selects ───┘                         │
  │                                                                 │
  └─────────────────────────────────────────────────────────────────┘

  IMPLEMENTAÇÃO:

  1. Adicionar: Plexers → Multiplexer
     - Data Bits: 32
     - Select Bits: 2 (para 4 opções)
  
  2. Conectar entradas de dados:
     - Input 0: ROM.data_out
     - Input 1: RAM.data_out
     - Input 2: Input_Buttons.data_out
     - Input 3: Constante 0x00000000 (padrão)
  
  3. Criar lógica de seleção:
     
     Precisamos gerar um código de 2 bits baseado nos chip selects:
     
     ┌──────────┬─────────────┐
     │ Select   │ Fonte       │
     ├──────────┼─────────────┤
     │ 00       │ ROM         │
     │ 01       │ RAM         │
     │ 10       │ Input       │
     │ 11       │ (nenhum)    │
     └──────────┴─────────────┘
     
     Uma forma simples é usar um encoder de prioridade ou
     combinar os chip selects com lógica.


9.6 AJUSTAR ENDEREÇOS PARA CADA COMPONENTE
-------------------------------------------

PROBLEMA: A ROM e RAM esperam endereços começando em 0,
          mas recebem endereços absolutos do processador.

SOLUÇÃO: Calcular o offset para cada componente.

PARA A ROM (0x0000 - 0x1FFF):
  
  - Endereço já começa em 0, não precisa ajuste
  - Apenas extrair os bits relevantes
  
  Implementação:
    1. Adicionar: Wiring → Splitter
    2. Entrada: addr[31:0]
    3. Saída: addr[12:2] para a ROM (11 bits de word)
              (ignora bits 0-1 porque são offset de byte)


PARA A RAM (0x1000 - 0x2FFF):
  
  - Precisamos subtrair 0x1000 do endereço
  - Ou simplesmente usar os bits internos
  
  Método 1: Subtração
    1. Adicionar: Arithmetic → Subtractor
    2. A: addr, B: 0x1000
    3. Usar resultado como endereço da RAM
  
  Método 2: Usar bits diretamente
    1. Usar addr[12:2] diretamente
    2. Funciona se o mapeamento for bem definido


PARA O VIDEO RGB (0x0400 - 0x07FF):
  
  - Já tratamos isso dentro do subcircuito Display_RGB_16x16
  - O subcircuito recebe o endereço completo e calcula internamente


PARA O INPUT (0x0900):
  
  - Endereço único, não precisa de ajuste
  - O subcircuito já verifica o endereço internamente
